# beta.21 部署门槛与下一阶段

当前状态：候选开发与隔离验收，不是部署授权；没有新版本发布或生产部署。完整恢复操作基础沿用[beta.20 部署与回滚方案](PERSONAL_CONSOLE_BETA20_DEPLOYMENT_ROLLBACK_PLAN.md)，制品、目标和版本须重新匹配 beta.21，不能直接拿旧制品代替。

## 何时可以部署

按下列顺序收口后，才能提出具体部署窗口：

1. beta.21 准确源码的三库、race、完整构建和页面回归通过，交付证据与独审齐备。
2. 维护者另行提供专用测试账号资料并授权受控测试。先确认旧 Codex OAuth/refresh 仍可用，再验证原生窗口、近似分额、正常请求和停止；不能把合成结果当作提供商兼容性证明。新版独立 SIWC 是另一个候选方案，当前未批准，不必预先把它作为旧路线部署的必需前提；旧路线若不成立，再明确替代方案。
3. 目标明确后按既有授权开展只读核查：当前版本、数据库和 writer、历史/未决义务、运行拓扑与恢复条件；按既有规则确认升级资格。历史冻结、legacy/bridge 轮换限制不得通过切 writer、清队列或改数据绕过。
4. 使用目标数据库原生工具，在授权的隔离恢复副本上完成可验证备份/恢复；固定准确制品摘要、配置差异、健康检查、维护窗口、恢复触发条件和负责人。
5. 维护者对该准确制品、目标和维护窗口明确批准部署后，才进入生产操作。

第1项CI仍在进行；第2至5项尚缺必要资料/授权，无法给出可靠日期。本批完成后可立即准备真实测试材料；“准备部署方案”“CI通过”“推送功能分支”都不等于已部署。

## 真实测试资料与推荐首轮

沿用[前置核查](PERSONAL_CONSOLE_OAUTH_PREFLIGHT_20261019.md)的推荐：一个专用、可撤销的订阅测试账号；单生成并发；主动试验20分钟、最多10次短生成、推理重试默认关闭。OAuth、refresh、sample、models各自预算及共同HTTP上限须在真实试验前按实际路线另行确认。当前控制能力最多1200秒/1000次总尝试/10次生成，是能力上限，不是批准消耗额度。

需要维护者提供或确认：账号套餐和共享关系、账号可用时间与手动授权方式、测试进程与临时数据库位置、允许的OAuth/refresh/查询/生成动作及预算、允许保存的脱敏窗口/错误字段、撤销与异常联系方法。不在聊天、仓库或截图中传真实凭据。授权将明确允许的凭据写入范围和销毁方法；现阶段不进行这些动作。

429只接受自然发生或已知可重复的合法测试条件，没有自然429就标为待验，不主动耗尽订阅。下一次原生窗口重置的观察时段另行确认。缺usage仍成功、Token未知；近似分额明确误差来源，不能伪造原生窗口或换算金额池替代。

## beta.21 特有的升级与回滚注意项

新增 `upstream_acceptance_runs` 为独立脱敏控制表，通过普通与快速迁移注册，不改旧表历史账务内容。升级与重复迁移的跨数据库证据须与候选对应。验收模式默认关闭；生产启用不属于本批，且该模式只是单进程、单账号范围，不能承诺跨集群停止或全进程网络隔离。

回滚前必须先停止隔离run并确认operation、HTTP及generation槽排空、无drain_error；凭据轮换后写入的安全结果不能用旧凭据文件覆盖。旧owner run不会被新进程续跑，旧表记录可以保留，不通过删表制造回滚成功。生产回滚仍以授权目标的原生备份/恢复和旧制品校验方案为准；本批没有执行任何生产备份、恢复或回滚。
