建议审阅顺序
1. 概览 → 上游账号 → 原生窗口：能否看清可用性、样本时间和受到影响的对象。
2. API Keys → 桌面应用 → 调整分额：20% 合法保存、60% 超配拒绝、0% 停止新请求、全池合计100%。
3. Key 暂停确认、恢复和估计分额耗尽：身份和本周期已有用量保留；已发送请求可能完成。
4. 调用记录 → 回答成功但 usage 缺失：始终区分请求成功、Token用量未知和窗口近似分额。
5. 调用记录 → 上游429、本地拦截：明确本次是否已经发送上游，未知不能推断为零。
6. 个人资料 → 加载成功或失败 → 重试；再走手机版本的主要流程。

原型中已确认的业务规则
百分比以明确选择的上游账号原生窗口为总池；同一真实账号不能重复建立100%总池。
同池分配总和不超过100%；未分配部分不自动借用，分额不预留上游容量。
修改比例保留本周期已估计用量，0%停止后续请求；近似计量、并发和在途请求可能超出。
示例：Key分配总窗口20%、估计使用总窗口5个百分点，显示已用所分额度25%。
多个原生窗口分别显示与配置，不能相加；可信上游观测确认重置后才进入新周期。
账号过期、观测过期、账号身份变化、窗口变化分别显示；不自动继承错误的池或切换未授权账号。
个人主流程不展示钱包、金额余额、充值、结算或历史核账表单。
上述是已确认的产品交互规则，不表示当前应用均已按新方案实现或经过真实上游验证。

本版原型限制
完整分额编辑以“桌面应用”这个现有Key为操作样本；另外两个Key展示各自正确身份与只读详情。
原生窗口分额以账号A的5小时窗口为完整操作样本；7天窗口用于展示独立观测与限制关系。
创建/轮换/删除Key、模型范围编辑、全新安装、安全设置编辑、账号身份变化后的重新绑定，以及同账号窗口变化后的重新选择，未展开完整操作原型。
这些不是删除功能的决定；需在后续原型修订中明确优先级。真实错误修复、数据迁移和应用验证均不在本轮。
