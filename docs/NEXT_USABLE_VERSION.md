### API Key 用量合同与当前迭代

- 真实消耗：以成功取得的上游 usage 为结算依据，覆盖非流式、流式终态、取消、重试与未知 usage；请求前估算用于预留，不当作已确认实际值。缺失或矛盾 usage 标记未知/待核对，不能补成零或虚称精确；并发限额和幂等结算必须保持。Token 总量默认按实际输入+输出，缓存输入和 reasoning 等已包含子项不再次累加。
- 费用预算：显示已用/上限而非充值余额。按实际模型、服务档位、上下文档位、币种和冻结价格版本计算；普通输入、缓存读取、缓存写入、输出及适用工具费用分别计价。OpenAI 来源须为其官网，不把现有 basellm.github.io 或 models.dev 第三方预设标成官网同步。同步保留来源、抓取时间、原始证据、价格差异、原子发布与回滚；解析/联网失败保持上次有效版本并显示过期，不默默写零价或覆盖管理员锁定值。
- 缓存：命中率用累计缓存读取 Token / 累计输入 Token，不平均每请求百分比；实际费用用逐请求实际分类 Token × 对应单价。文本输入成本为 (输入总数−缓存读取−缓存写入)×普通输入价 + 缓存读取×缓存价 + 缓存写入×写入价，再加输出及适用费用；分类字段须验证，不允许负数或重叠重复计费。不同模型规则不得套统一倍率。
- 百分比：保持账户及窗口（短窗口/周窗口等）的真实身份、重置时间与新鲜度；跨账号百分比不能简单相加。账号总体前后差值无法在多 Key 并发或外部调用下可靠归属单个 Key，未确认口径前不伪造逐请求百分比消耗。待用户确定是账户剩余安全阈值，还是每个 Key 在每个账户窗口内的独立百分比预算；后一种需要可归属的上游事实。
- 官方 API 价格只表示直连 API 的适用费用；通过订阅账号/Codex 渠道计算的官网 API 等价费用应明确标为参考成本，不能冒充订阅商户实际扣款。
- 阶段顺序：先收口真实 usage 与缓存成本证据，再做官网价格同步、API Key Token/费用预算界面与硬限制，最后接入已确认的账号百分比规则。沿用同一 R1，不同时扩展支付功能。当前尚未通过上述新合同验收，跨模块实现方案在百分比口径确定后细化，不擅自沿旧钱包模型实现。

### 未知用量收口的规则确认点

日志标记之外必须提供可恢复的未知状态，不能只return跳过结算、把金额猜成0或退款。原2daa已存在实时请求的usage_unknown冻结、审计和人工恢复；候选未纳入，而且原接口对legacy仅保留进程内状态，不构成完整新预算保证。只复用其中已核对的变更块，不整包移入其他WIP。
