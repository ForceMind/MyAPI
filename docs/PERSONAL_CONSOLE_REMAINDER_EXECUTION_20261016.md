## 实施顺序与边界

1. 主线程补充 Root 专用 `GET /api/subscription-share/pools/:pool_id/usage`，读取一致事务快照。仅暴露白名单 Key 身份/状态、配置比例、当前周期估计与请求状态，不返回明文 Key、账号主体指纹、请求标识或凭据。owner 与普通管理员均无全池读取权限。
2. 从当前 generation 的不可变 `baseline` / `reset_baseline` 样本证据读取周期初始基线；`BaselineUsedMicro` 可在显式重新观测时改变，不能直接冒充最初启用前占用。缺证据或分解不一致时使用 null/未知，保留真实总量和理由，不补零或修写历史。
3. 上游页面按明确账号、原生窗口、pool 及当前会话读取；把配置比例与用量构成分开，列全部 Key（含已删除身份的历史占用），显示新鲜度、近似限制、加载/失败/重试。大列表保留完整可访问入口，不用假图省略数据。
4. 核对 Key 高级维护与恢复入口，已批准范围内的缺陷修正与对应行为测试一并完成。未展开的全新产品流程如确有关键选择，再单列决定。
5. 主线程完成七语言和候选 `0.2.0-beta.16` 元数据（远端对应 tag 当前不存在）；Actions 执行类型、lint、构建、测试、三库与 Chromium。非实现者审查代码和原始桌面/手机截图；归档证据，提交/推送同一分支并更新现有 Draft PR #17。
