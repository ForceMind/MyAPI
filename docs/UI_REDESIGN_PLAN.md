# My API UI 渐进重设计方案

日期：2026-09-09。状态：用户已于本任务确认实施，首批概览与渠道改造进行中。用户要求重新设计概览、渠道 UI 和交互逻辑，并按计划逐步替换其余 UI。

## 现状与交付范围

已部署版本为 0.1.4，来源 `67996ab9a7c1c5044aa9d47f3eb47168dd4c197d`；最近部署文档提交 `de370f4`。沿用 React 19、Base UI、Tailwind、TanStack Query/Router、VChart 和已有权限。构建及完整验证继续在 GitHub Actions 执行，不在服务器重新建立 Go/前端编译缓存。

本方案先覆盖概览与渠道，并建立两页真正需要的公共规范；其余页面列迁移顺序，不在一次确认中直接改完所有业务页面。不改变额度扣费、渠道选择算法或生产智能分配开关。两页行为梳理需要的只读数据汇总、预览与保存反馈列入实施范围，接口变化保持三库兼容。

当前问题的代码依据：

- `web/src/hooks/use-sidebar-data.ts` 同时有概览和 Dashboard 入口，需要用概览/用量分析明确职责，保留 URL。概览中的 Route active 由 API 信息配置数量推断，不能当渠道健康证据；实现时移除该推断。

- `web/src/features/dashboard/components/overview/overview-dashboard.tsx`：大型接入引导排在 SummaryCards、AccountQuotaChangesPanel 之前，随后还有多组信息面板；首屏职责分散。
- `.../overview/summary-cards.tsx`：总用量、账户额度和预计可用时长混排，必须区分账户余额与上游渠道剩余。
- `.../overview/performance-health-panel.tsx`：对模型 success_rate 进行 simpleAverage，不能直接称为请求级整体成功率。
- `web/src/features/channels/index.tsx`：已有渠道管理、额度分析、流量分配页签，保留路由与深链接，不重新拆成多个无关联入口。
- `web/src/features/channel-routing/types.ts`：现有预览只有 model/group/path，读取已保存规则；当前并无服务端草稿预览契约。现有配置更新使用 expected 值防止并发覆盖，必须保留。

## 视觉与布局规则

采用克制的管理后台样式：中性底色、单层面板、明确的文字层级，颜色主要表示状态与不同渠道。复用现有品牌资产、主题和组件，不以设计稿字母图标替换真实品牌。页面标题、页签、工具栏、列表/图表、状态反馈使用统一顺序。

- 标题区只出现当前任务需要的主要动作；表格批量操作仅在选择行后出现。
- 标准间距以 4/8/12/16/24 为基础；主内容宽度与现有侧栏协调，不重置其他页面的全局布局。
- 图表优先占可用空间，常用操作一行或自然换行；说明、诊断与少用选项折叠。1280×720 下概览/额度图的时间轴可见。
- 桌面渠道用表格；手机用紧凑列表或明确的局部横向滚动，保留名称、状态、当前额度、操作，整页不横向溢出。
- 添加/管理渠道使用同一详情面板；手机全屏，桌面侧边面板。键盘关闭、焦点恢复、未保存变更提示明确。
- loading、无样本、未授权、失败、过期、保存中、冲突分别显示，失败不得伪装成 0 或“正常”。
- 七种语言、明暗主题、键盘操作、低动画偏好沿用项目机制。

## 第一批：概览

目标：管理员能看清运行状态、当前额度以及需要处理的事项。普通用户只看到自己的账户与请求信息；渠道及全局统计严格遵守能力权限。

桌面顺序：

1. 标题与统计时间范围，展示更新时刻。
2. 四项摘要：期间请求量、请求级成功率、当前启用渠道、当前分配模式。启用数量不等于实际可用数量；若展示可用状态必须包含禁用、额度、模型及数据新鲜度判定。
3. 渠道剩余额度主图：按相同单位/额度窗口分组，多渠道同图；固定渠道颜色；入口直达渠道额度分析并带渠道/时间范围。
4. 需要关注：采样失败/过期、额度耗尽、渠道异常等已证实状态。低额度提示使用现有可配置阈值，不能把设计稿 28.6% 当业务阈值。智能分配关闭为提示，不当故障。
5. 近期切换摘要与接入帮助；只读呈现现有日志 `other.admin_info.channel_routing`，必要时补充 usage-logs 类型与详情字段，不暴露会话 ID 或哈希；完整向导按需打开，新账户仍能发现引导。公告、API 信息、FAQ、Uptime Kuma 保留现有配置与访问入口。

数据口径：

- 请求量/成功率必须有相同作用域、起止时间和去重口径；请求级成功率 = 成功请求数 / 总请求数，零请求显示暂无请求。不能跨来源拼接不一致分母，不能对模型百分比简单平均。
- 优先复用现有服务端汇总；前置核实原始请求、重试次数与成功定义。如果缺少可靠分子/分母，增加有时间界限的只读汇总，不能前端全量拉取日志。展示前注明口径。
- 上游剩余百分比分别展示，不相加、不与平台用户余额混称。未知和过期有显式状态。
- 页面切换和切换账号隔离查询缓存；只请求当前权限和当前视图需要的数据，重复面板共享查询。

## 第二批：渠道

保留 `/channels` 与现有 `tab`、`quotaChannelId` 深链接；已有完整配置、复制、测试、模型发现、OAuth、多密钥和批量操作保持可达。

### 渠道管理

列表常用列为渠道名称/模型概况、启用状态、额度与采样时间、使用顺序、同级权重、管理操作；高级字段用列设置或详情呈现。

- 渠道启用状态只有一个权威开关。关闭后不进入候选；后台保存失败恢复旧值并显示原因。
- 使用顺序显示优先/常规/备用，数字属于底层存储。未知历史优先级显示自定义并原值保留；打开界面不归一化旧配置。
- 权重显示相对份数，不假装是全局固定流量百分比。只在模型、分组、优先级等候选条件相同后解释比例。正常输入要求正数，历史零值明确引导处理，不静默启用或丢失旧状态。
- 搜索/筛选/分页保留；已选行、编辑草稿与保存状态相互独立。

### 额度分析

保留 0.1.4 已验证的数据与图表能力：多渠道剩余曲线，折线/柱状/散点/面积；剩余变化推算用量；图内滚轮缩放、手动范围、上游周重置周期；原始采样精度、明确截断和断点；图外滚动页面。

主工具栏只有指标、可比较额度窗口、图型；渠道图例可选择。时间范围与缩放状态共用一个来源，缩放后重新请求对应范围，不仅放大旧图。周期由指定渠道 reset_at 对齐，其他渠道同绝对时间轴；缺 reset_at 要求选择锚点，不猜周一。补额与重置不形成负用量，不跨缺失区间推算。失败原因与诊断默认折叠且可达。

### 流量分配

依次为：当前模式与开关 → 两条 Chat/Codex 规则 → 对话保持与故障切换 → 渠道顺序/权重 → 分配预览与保存结果。

沿用已确认业务：按请求接口判断任务，普通 Chat 更偏向当前剩余少的一组同类渠道，Responses / Codex 工作流偏向当前剩余多的一组（保留现有高低剩余分池，不能改成固定挑选极值）；先满足模型/分组、可用性与优先级条件；同一对话保持渠道，故障或耗尽允许切换并记录原因。额度不可比较/过期时解释回退，不跨单位排序；指定渠道令牌保留原语义。其他接口保留既有分类。对话缺少可靠标识时不得承诺强绑定。

保存与预览契约：

- 主开关读取服务器真实状态，不能因 UI 改版自动启用。
- 对已保存规则的预览与草稿预览明确区分。第一步保留既有真实预览；若使用设计稿中的“预览当前草稿”，必须在服务端复用同一选择逻辑，允许经校验的临时覆盖，不写数据库、不触发真实模型调用，不在前端复制调度算法作为正式依据。
- 草稿值、已保存值和预览所用版本显示一致。变更后旧预览标记过期；提交在处理中禁用重复操作。
- 保留 expected 值与权限检查。多个保存请求不能显示为虚假的一次成功：采用逐项可追踪结果并只重试失败项，或在必要时新增经批准范围内的事务更新契约。409 保留草稿并给出重新加载/比对入口。
- 渠道测试会产生真实上游请求，必须是独立的显式动作，不能混进预览或保存。
