## 必须保持的行为

- 个人主流程不显示钱包、金额余额、充值、结算、人工核账表单；这不授权删除历史数据或后端安全约束。
- 完整回答且上游没有 usage：请求成功与用量未提供分开展示；输入/输出Token未知，不填0，不要求管理员核账才能视为成功。
- 份额100%以选定真实渠道订阅账号的明确原生窗口为总池；多个窗口分别表达，不相加，同一账号不能重复建多个100%总池。
- 上游整体占用不能冒充准确逐Key归因。近似分额明确误差、新鲜度、未归属和待计状态；未知证据不得自动算成0或精确统计。
- 同池配置总和不超过100%；20+其他50=70可保存、60+50=110拒绝；100合法但不预留容量。0停止后续新请求且保留已有用量。
- 调整比例保留当前周期已有估计用量。使用总窗口5个百分点、分配20%，已用占所分额度25%。不能混淆百分比与百分点，不能用Token强行推算窗口消耗。
- 近似分额仍可能因单次、并发、在途请求和采样延迟超出；重置须依据可信上游新周期证据，不随刷新或改比例清零。
- 工作台进入聊天沿用明确选择的现有Key并验证当前用户/会话；不能悄悄回退到更宽Key或自动发送生成请求。
- 个人资料管理范围“仅本人”只读；超时和失败提供恢复入口，不无限加载、不显示假资料。
- 后续未展开的Key新建/轮换/删除、模型范围编辑、完整安装、安全编辑、账号改绑和窗口重选保留为后续设计范围，不能静默删功能或宣称已完成。
