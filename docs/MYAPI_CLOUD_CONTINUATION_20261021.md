## C1：取消读取不再冒充服务错误

原共享 Axios 响应拦截器对所有非 401 拒绝调用 `toast.error`。统计观察者退出或切换时主动取消读取，虽然请求正确拒绝，仍会显示 `canceled` 等错误提示。

仅在共享响应错误分支入口判断 Axios 的正式取消标识 `axios.isCancel(error)`，原样抛回同一错误，让调用方保留取消与清理语义，同时不触发服务错误提示。没有按字符串、所有请求失败或宽泛的 abort/timeout 名称屏蔽错误。

回归覆盖：

- AbortSignal 在派送前已取消，不能派送 HTTP 或弹出服务错误。
- CancelToken 与适配器取消保留原拒绝对象，不显示错误。
- 统计新观察者不复用被取消的旧读取，新结果正常返回且旧取消不提示。
- HTTP 401 / 403 / 503、网络失败、`ECONNABORTED` / `ETIMEDOUT` 仍按既有规则提示并拒绝。
- 普通错误即使消息为 `canceled` 也不能被隐藏。

先在未修复生产源码上运行新测试：11 项中 4 项按预期失败，均为取消时错误通知被调用；其余 7 项通过。加入生产修复后同一组 11 / 11 通过。测试使用真实 Axios 请求与拦截器，只替换网络适配边界，不复制被测逻辑。

### 关系事实与权限

Root 的 `GET /api/token/:id/subscription-share` 同时包含可配置的 candidate 窗口；有正 `pool_id`、相同 `channel_id`、非 closed 也不能证明该 Key 已分配到此池。因此新增 Root-only、no-store 的 `GET /api/subscription-share/channels/:channel_id/pools?page=N`：从已有池和持久 `SubscriptionShareAllocation` 子查询读取，不创建 schema、不刷新供应商、不推进分额投影、不读取 Key 明文。每页最多20池（加一条探测下一页），按稳定池 ID 排序；模型层再次读取当前操作者 role/status，拒绝非 Root/停用操作者。候选但无 allocation 的池不列入；关闭池、零份额、删除/过期 Key 的历史 allocation 不被擦除，也不被描述成当前路由授权。

池内关联来自既有 Root-only pool usage 的 `allocations[].token_id`，同时验证准确池和 channel ID；不按名称匹配，不调用 token 搜索或 Key 明文接口。`/keys` 新的关联视图使用结构化 `connectionContext`，保留连接列表筛选、状态、页码、连接 ID、分额池列表页和选中池/Key。旧普通 Key 列表和 `/channels` 高级操作仍保留。

每次进入关联视图先以当前会话验证新鲜 Root 身份；错误、换账号/会话、角色撤销隐藏旧数据与编辑器，读取使用独立 AbortSignal。只有真实 allocation 且 Key 仍存在、池未关闭才提供编辑；显式点击后复用既有分额对话框，并限定准确 pool/channel，不自动选择窗口，不改变写入/幂等/确认协议。关闭、取消、切换 Key、返回不会重新打开旧编辑器。
