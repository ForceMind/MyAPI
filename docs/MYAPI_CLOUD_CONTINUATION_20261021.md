## C1：取消读取不再冒充服务错误

原共享 Axios 响应拦截器对所有非 401 拒绝调用 `toast.error`。统计观察者退出或切换时主动取消读取，虽然请求正确拒绝，仍会显示 `canceled` 等错误提示。

仅在共享响应错误分支入口判断 Axios 的正式取消标识 `axios.isCancel(error)`，原样抛回同一错误，让调用方保留取消与清理语义，同时不触发服务错误提示。没有按字符串、所有请求失败或宽泛的 abort/timeout 名称屏蔽错误。

回归覆盖：

- AbortSignal 在派送前已取消，不能派送 HTTP 或弹出服务错误。
- CancelToken 与适配器取消保留原拒绝对象，不显示错误。
- 统计新观察者不复用被取消的旧读取，新结果正常返回且旧取消不提示。
- HTTP 401 / 403 / 503、网络失败、`ECONNABORTED` / `ETIMEDOUT` 仍按既有规则提示并拒绝。
- 普通错误即使消息为 `canceled` 也不能被隐藏。

先在未修复生产源码上运行新测试：11 项中 4 项按预期失败，均为取消时错误通知被调用；其余 7 项通过。加入生产修复后同一组 11 / 11 通过。测试使用真实 Axios 请求与拦截器，只替换网络适配边界，不复制被测逻辑。

## 下一切片：连接详情到排错的双端闭环

源码核查确认渠道页仍将旧 `ChannelsTable`、额度图、事件和路由预览堆在同一页。`ChannelsTable` 的手机判定仍为 640px，和平台计划的双端组合不一致；卡片只是复用旧表格 cell，不能当作新的移动管理流程已经完成。

接下来的有界实现应是“连接清单 → 连接详情 → 既有编辑 → 已筛选调用记录 → 返回原连接”，而不是再改一轮导航名称：

1. 保留 `/channels` 的书签、服务端分页筛选、权限与既有高级操作。以稳定渠道 ID 选中连接，PC 显示清单与详情，窄屏进入有明确返回的详情；离开、取消、Back / Forward 与重开均保留正确上下文。
2. 详情从已有渠道读取、模型路由和已保存窗口证据组织供应商、模型、路由与最近观测。账号关联必须有现有可信 ID；不能按显示名合并账号，也不能把“没有窗口”写成“没有渠道”。
3. 复用 `ChannelMutateDrawer` 的验证、权限与写入语义。详情浏览不触发供应商测试、余额查询、模型发现或认证刷新；这些仍为明确的既有动作。
4. 关联请求使用 `/usage-logs/common` 已有 `channel` 服务端过滤。Key 关联只展示现有可证明关系，不能暗示每个 Key 必然只属于一个渠道，不能增加隐式授权。
5. 合成验收包含普通 API 与订阅连接、无窗口、观测失败、长中文/英文、空列表、403 / 503、取消和重复操作。验证 320 / 390 / 768 / 1024 / 1280 / 1440 宽度及键盘、焦点、滚动、返回，不用截图数量或 CI 绿灯代替实际任务可用性。
