## 0. 结论摘要

1. 三个方向都不再用第一版的"240px 分组侧栏 + 统计大卡 + 列表 + 右侧检视器"组合，各自的导航模型、首页形态、对象呈现方式都不同（第 2 节）。样稿可以点：开关、行内展开、三栏选中、哈希路由的页面堆栈、节点筛选、页签、对话框 **[查看]**。
2. **推荐方向 1「切换台」作为三个版本共用的设计语言，并把方向 2「控制室」的"上游矩阵 + 请求流"作为 Full 版概览的一个可选视图。** 理由见第 4 节：它在维护者的高频任务上步数最少、手机友好度最高、与"本地版像个人效率工具"的要求最贴合、实现代价最低。
3. 对比度：三个方向亮暗共 105 个关键组合，104 个通过（正文 ≥4.5:1，非文本 ≥3:1）；唯一不通过的是 Logo 青 `#00CFFC` 直接放在白底（1.85:1），三个方向都规定青色在亮色表面只作深青 `#0083A8` 的点缀或用于深色外壳 **[运行]**（附录 A）。
4. 第一版实现的处置：外壳、令牌值、三个关键页布局需要重写；数据钩子、版本能力读取、Request ID 直达、术语表、i18n 短键、对比度脚本等保留（第 5 节）。估算返工：外壳与令牌约 2 批次，三个关键页约 1.5 批次，和第一版当初的工作量相当 **[猜测]**。
5. 需要维护者拍板的问题 8 项（第 6 节），其中最关键的是选方向、以及 Desktop/Lite 默认首页是否改为"接入"页。

## 1. 用户与高频任务

高频任务沿用第一版 1.2 节的 10 项，下表给出三个方向的步数。"步数"= 从已登录首页出发到完成任务的点击次数，不含输入；方向 1/2/3 的数字是按样稿实际走一遍数出来的（任务 1、2、4、6、7 **[查看]**），其余按设计推算 **[猜测]**。

| # | 任务 | 现状 PC / 手机 | 方向 1 切换台 | 方向 2 控制室 | 方向 3 流向图 |
| --- | --- | --- | --- | --- | --- |
| 1 | 查一个 Key 的最近请求并看失败原因 | 4 / 4 | 2 / 3（Key 行展开 → 点请求 → 对话框） | 2 / 3（选 Key → 选请求，右栏即详情；手机三屏） | 3 / 3（Key 表 → Key 页 → 请求页） |

## 2. 三个设计方向

三者共用的东西：Logo 不变；深蓝 `#0035FC` 只作操作色（主按钮、选中、链接、开关开启）；Logo 青只作"流动数据"的非文本标记，亮色表面用深青 `#0083A8`，深色表面可用 `#22D3FF`/`#00CFFC`；状态一律"徽标 + 圆点/图标 + 文字"，不整行着色；数值未知显示"未知"/"—"而不是 0；"用量可信度 / 结算 / 业务结果 / HTTP 状态"四项分开显示（平台方案第 7 节）；术语表沿用第一版 5.4 节（连接、账号窗口、API Key、调用记录）。

### 2.1 方向 1「切换台」——卡片化的个人效率工具（推荐）

- **一句话定位**：像一个本机工具：一列对象，一个开关，剩多少写在脸上。
- **气质关键词**：安静、温和、单列、可直接动手。
- **色彩与字体**：暖灰纸底 `#F6F5F1` + 白卡 `#FFFFFF` + 深墨 `#1D1C19`；主操作深蓝 `#0035FC`；选中/当前态淡蓝 `#EEF1FF`/`#0029C4`；状态绿 `#1B7A3E`、琥珀 `#8A5300`、红 `#C2261D`、信息蓝 `#0B5E8F` 各配柔和底色；额度条深青 `#0083A8`（≥60% 琥珀、≥80% 红）。暗色：`#171613` 底、`#201F1B` 卡、`#ECE9E1` 字、主色 `#8EA6FF`、额度条 `#22D3FF`。字体：系统 UI 栈（中日文按 `:lang()` 切换到 PingFang / Hiragino / Noto），正文 14px，手机 15px，标题 22px；等宽用于地址、Key、ID。对比度 36 个组合全部通过（附录 A，唯一例外是规定不用的"青色直接放白底"）**[运行]**。
- **信息架构与导航**：
  - PC：左侧 232px 窄栏，只有 5 个主入口（接入 / 上游 / API Key / 请求 / 用量）+ 底部"设置"与"本机接入地址 · 版本"小卡；内容单列，最大宽 1080px；页面标题 + 一个主按钮；没有面包屑、没有顶栏。Full 版在栏底增加"用户 / 商业 / 系统"三个折叠入口。
  - 手机：顶栏（Logo + 页面标题 + 主操作图标 + 搜索）+ 底部 5 项（接入 / 上游 / API Key / 请求 / 更多）；同一列内容；展开与对话框全屏化。
- **首页形态**（`mockups/1-switchboard/home.html`）：第一块是"需要处理"（有事才显示），第二块是**本机接入卡**（Base URL、访问模式、复制、环境变量 / curl 片段），然后一行 4 个小统计块（今天请求 / 失败 / 耗时中位数 / 用量未知），最后两列：最近请求（5 行）和上游状态（每行剩余百分比 + 可用/失败徽标）。
- **核心对象呈现**：上游和 Key 都是**一行一张卡**：头像 + 名称 + 类型小标签 + "正在使用"标记；行右侧是额度文字 + 细进度条 + 测试结果徽标 + 测试按钮 + 启用开关。点行**在原地展开**（额度窗口 / 路由 / 操作；Key 则是最近请求 / 范围与分额 / 交付三个页签），不离开列表。
- **关键交互**：开关即启用；播放图标即测试；展开即详情；请求详情是居中对话框（手机全屏），页签 诊断 / 正文 / SSE；首页顶部"正在使用 A · 备用 D · B 因测试失败暂未参与路由"一句话说清路由现状。
- **七语言长文本**：导航只有 5 个短词，各语言给独立短键；行卡的名称与地址可截断（带 Tooltip），标签与按钮不截断可换两行；额度文字用"5h 剩 18%"一类数字优先的写法减少词长；320 宽度下行右侧区域换行到第二行（样稿已实现 **[查看]**）。
- **三个版本**：Desktop/Lite 首页是"接入"；Full 首页同样布局，但本机接入卡换成"接入地址 + 访问模式 + 用户与分组摘要"，侧栏多三个折叠入口，列表多一个"范围"筛选。三个版本共用同一套组件，只按能力显隐。
- **优点**：任务 1/5/6/7/9 步数最少；手机不是缩放而是同一列模型；与"本地版像个人工具"的要求一致；可复用 shadcn 的 Card / Collapsible / Switch / Dialog / Tabs。
- **缺点**：Full 版 30 多个入口要靠折叠；Key 或上游超过 ~30 个时单列行卡扫视效率低于表格（需要搜索与筛选顶住）；行内展开让页面高度变化，需要保持滚动位置。
- **实现代价**：外壳重写（`console-shell.tsx`、`console-sidebar.tsx`、`console-header.tsx`、`mobile-bottom-nav.tsx`、`app-breadcrumb.tsx` 去掉）；`theme.css` 令牌改值 + 新增 `--meter`、`--*-muted`；三个关键页的布局重写，但 `features/keys/components/inspector/key-inspector.tsx`、`features/connections/connection-inspector.tsx` 的内容区可以改成行内展开面板直接复用。估算：中。

### 2.2 方向 2「控制室」——高密度运维

- **一句话定位**：一屏看全：矩阵、事件、请求流、状态栏，像一个值班台。
- **气质关键词**：密、冷、等宽、常驻。
- **色彩与字体**：**固定深色外壳**（顶栏、图标栏、底部状态栏 `#0B1220`，文字 `#C6D0E5`），内容区亮色 `#EEF2F8`/白 或暗色 `#0A0F1C`/`#121A2B` 随主题切换；实时计数用 Logo 青 `#22D3FF` 放在深色外壳上（对比 11:1 以上，这是三个方向里唯一能让青色当文字用的地方）；状态色与方向 1 同系但更饱和；正文 13px、表格 12.5px、行高 32px；ID、时间、数值一律等宽。对比度 41 个组合全部通过 **[运行]**。
- **信息架构与导航**：
  - PC：顶部 48px 深色栏（品牌 + 版本标签 + 居中命令框"粘贴 Request ID 回车直达" + 右侧实时计数 RPM / 失败 / 上游可用 / 用量未知）；左侧 68px 图标栏（图标在上、11px 标签在下：概览 / 上游 / Key / 请求 / 正文 / 用户 / 分析 / 商业 / 设置）；底部 26px 状态栏（运行状态、实例版本、数据库、后台任务、最近采样、时区、快捷键提示）。
  - 手机：深色顶栏（返回 / Logo / 标题 / 版本 / 搜索）+ 深色底部 5 项；多栏改成"列表 → 对象 → 请求"三屏堆栈（哈希路由 `#key/21`、`#req/0`、`#conn/2`），表格在手机上变成"时间 · 结果 · 耗时 / 模型"两行记录，不横向滚动（样稿已实现 **[查看]**）。
- **首页形态**（`mockups/2-control-room/home.html`）："运行板"：一条紧凑统计带（6 个数 + 每小时请求 / 失败两条迷你直方图）；左 2/3 是**上游矩阵**表（连接 / 类型 / 状态 / 5h / 7d / 最近测试 / RPM / 启用开关）和**请求流**表（带 全部 / 失败 / 用量未知 / 待核对 筛选）；右 1/3 是事件时间线、后台任务、实例信息。
- **核心对象呈现**：表格行；选中行高亮；右侧 372–400px 检视栏常驻。Key 页是三栏：Key 列表 | 该 Key 的请求表 | 请求检视（四格结果 + 元信息 + 诊断 / 正文 / SSE / 原始）。上游页是两栏：矩阵表 | 连接检视（最近测试原文、窗口、路由、近 7 天直方图、操作）。
- **关键交互**：↑↓ 选择、Enter 打开、J/K 上下条、Esc 回列表、⌘K 命令框；开关与测试都在行内；30 秒自动刷新。
- **七语言长文本**：图标栏标签限 1–2 个词（各语言短键），超长则只显示图标 + Tooltip；表头用短键；表格列按优先级在 1024–1279 自动隐藏低优先级列（`.lo`）；手机转两行记录。
- **三个版本**：Full 完整；Lite/Desktop 隐藏"用户 / 商业"图标，状态栏去掉多实例信息，首页"实例"块换成"本机接入"块。
- **优点**：任务 9、10 做到 0 步；排错路径最短且不换页；上游矩阵最接近维护者"多渠道/账户剩余额度同图"的历史需求（`MYAPI_MASTER_PLAN.md` sub2api 一节）。
- **缺点**：对 Desktop/Lite 的单人用户过于"值班台"，与"个人效率工具"气质相反；固定深色外壳在亮色模式下对比强烈，部分用户不喜欢；三栏在 1024–1279 宽度要退化为两栏 + 覆盖层；手机只能做查看，复杂操作仍需 PC。
- **实现代价**：外壳重写（新的顶栏、图标栏、状态栏，三组件）；`data-table` 可复用但要加紧凑行高、键盘导航与选中态；检视栏可复用第一版的 `key-inspector.tsx` / `connection-inspector.tsx`；三栏布局与哈希/查询参数同步逻辑新写。估算：中高。

### 2.3 方向 3「流向图」——拓扑优先、顶部导航的产品式页面

- **一句话定位**：首页画出"谁在调用 → 网关 → 落到哪个上游"，其余都是对象页。
- **气质关键词**：开阔、产品化、以对象为页、一次只看一件事。
- **色彩与字体**：纯白底 `#FFFFFF` + 浅灰面 `#F3F5FA` + 墨 `#0C1222`；顶部导航当前项用深蓝下划线；首页中央"网关核心"卡用深蓝底白字，Logo 青只作其中的柱状标记（非文本，3.89:1）；额度用环形（深青 / 琥珀 / 红）。暗色：`#090D18` 底、`#131A2A` 面、核心卡 `#1C2752` 上允许青色文字（7.75:1）。字体同方向 1，标题 24px，圆角 14px。对比度 28 个组合全部通过 **[运行]**。
- **信息架构与导航**：
  - PC：顶部 56px 横向导航，只有 5 项（概览 / 上游 / API Key / 请求 / 设置）+ 右侧搜索与头像；内容 1200px 居中；对象页用面包屑（最多三级），**没有侧栏、没有检视器**，每个对象是一整页（哈希路由堆栈）。
  - 手机：顶栏（返回 / Logo / 标题 / 搜索）+ 底部 5 项；流向板变成纵向"Key 列表 → 网关卡 → 上游列表"的管道；对象页同 PC 但单列。
- **首页形态**（`mockups/3-flow/home.html`）：流向板三列——左 Key 节点（今天次数、失败数、状态点），中网关核心卡（接入地址、今天 / 失败 / P50、每小时柱状、版本与访问模式），右上游节点（环形剩余、优先级、使用中 / 测试失败）；点任一节点，下方请求表按它筛选并出现可清除的筛选标签 **[查看]**。
- **核心对象呈现**：列表页是表格（Key）或 3 列卡片网格（上游，卡上有环形、状态、开关、测试）；对象页是"标题 + 徽标 + 操作 | 三个统计块 | 页签（请求 / 范围与分额 / 交付；窗口 / 路由与模型 / 请求 / 历史）"；请求页是"四格结果 + 左诊断时间线 + 右正文/SSE/原始"。
- **关键交互**：节点筛选；页面堆栈的返回；卡片开关与测试在卡上；对象页页签。
- **七语言长文本**：顶部导航只有 5 个短词，俄语 / 法语长词时允许两行或缩成图标 + 文字（≥1280 不会溢出，1024–1279 需要收起一项到"更多"）；面包屑可换行；卡片网格 1024–1279 变 2 列。
- **三个版本**：Lite/Desktop 的核心卡显示本机地址与访问模式；Full 的核心卡显示公网地址与"用户 / 分组"摘要，顶部导航多一项"管理"（下拉：用户 / 商业 / 系统）。
- **优点**：首页一眼讲清整条链路，对新用户最直观；对象页信息完整、不拥挤；手机与 PC 的差别最小化为"列数"。
- **缺点**：任务 1、7 步数比方向 1 多 1；Key 或上游超过 ~8 个时流向板要折叠成"前 N 个 + 查看全部"，拓扑感会减弱；顶部导航在七语言与 Full 版入口数上有压力（第一版已指出的问题，这里用 5 项 + "管理"下拉缓解）；页面堆栈切换比行内展开慢。
- **实现代价**：外壳重写为顶部导航；流向板是全新组件（节点、连线、筛选联动）；对象页布局新写，但可复用 `data-table`、第一版的检视器内容区做对象页主体；请求页新写两栏。估算：高。

## 3. 三个方向对比

| 维度 | 方向 1 切换台 | 方向 2 控制室 | 方向 3 流向图 |
| --- | --- | --- | --- |
| 任务 1 查 Key 失败请求（PC / 手机） | 2 / 3 | 2 / 3 | 3 / 3 |
| 任务 5 看窗口剩余 | 0 | 0 | 0 |
| 任务 7 暂停 Key | 1 | 1 | 2 |
| 任务 9 失败汇总 | 1 | 0 | 1 |

## 4. 推荐与理由

**推荐方向 1「切换台」作为三个版本共用的设计语言；把方向 2 的"上游矩阵 + 请求流"做成 Full 版概览里的一个可切换视图（"运行板"），不另做外壳。**

理由：

1. 维护者的原话强调"本地版"与 CC Switch，Desktop/Lite 是自用场景，方向 1 的"一行一个对象、开关在行上、剩余写在脸上"最直接对应 `RESEARCH.md` 第 2.2 节的 C1–C4，又不复制 CC Switch 的结构（MyAPI 没有工具列表、没有三模式页签、用的是行内展开而不是编辑弹窗）。
2. 在 10 个高频任务里方向 1 有 7 项并列最少或最少，没有一项最多；方向 2 只在 9、10 两项更好，而这两项正是"运行板"视图能补上的。
3. 手机端三者里方向 1 最不需要特殊处理：同一列模型，展开与对话框全屏化即可，320 宽度下只是右侧区域换行 **[查看]**。
4. 实现代价最低：外壳是三个方向里最简单的（无顶栏、无面包屑、无状态栏），对象页可直接复用第一版两个检视器的内容区。
5. 方向 3 的流向板很有辨识度，但它是全新组件且在对象多时退化；建议把它的"网关核心卡"思路吸收进方向 1 的本机接入卡（已经这么做了），拓扑图本身留作以后"分析"页的可选视图。

如果维护者更看重 Full 版的运维密度，备选是方向 2 作主语言、方向 1 的行卡作 Lite/Desktop 的首页——但那样两套外壳会违反"三个版本共享同一套设计语言"，所以不作为推荐。
