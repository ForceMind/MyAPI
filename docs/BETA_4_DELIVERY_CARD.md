## 本轮真实缺口

1. 模型获取接口仅返回 ID 列表，页面缺少可恢复的发现来源/时间/失败后旧证据；
   上游更新当前记录最近检查时间，不能据此证明最近成功或配置身份仍匹配。
2. 公共名与上游模型映射、端点约束、冲突反馈未形成同一可查看任务流程；
   不能继续让预览只列渠道而隐藏实际目标。
3. 当前预览列 priority/weight，明确未评价 affinity；模型映射、协议资格、
   现有权限及运行时排除条件需要与真实发送复用相同判定，并明确预览边界。
4. 日志已有 upstream_model_name，但尚缺完整本次路由依据/配置证据及端点归因；
   必须核对初次、重试、详细测试与实际派送，防止别名绕过限制和适用价格。

目录证据与显式启用模型分开，发现不自动新增权限或预算资格。严格预算现有
不合格映射拒绝规则保留，不把 beta.6 资格扩展提前做。必要持久数据优先用

## 验收、依赖和恢复

- 两个受支持合成上游、一个公共模型：添加→获取或明确手填→显式映射→
  预览→详细/快捷测试→实际应用请求→日志可核对真实目标和原因。
- 精确/端点/最长前缀/优先级规则只有声明支持才开放；同优先冲突、越权、
  无候选、配置变化、空列表、获取失败/过期都有明确结果，不任意取第一项。
- 发现失败保留旧证据并标状态；重复获取幂等，不自动删除/开放映射；
  配置并发变化不能让旧获取结果冒充新配置证据。
- 资金/权限回归：映射后的真实目标、预算资格和冻结价格不能被别名绕过；
  原 unknown/estimated 保留、明确0、Root幂等恢复、账户阈值不退化。
- 最小相关 Go/前端测试先行，必要三库配置/日志/恢复合同接入既有 CI；
  root Go 和 relaykit 独立构建分别验证。七语言/typecheck/lint/build 和
  实际渲染记录随同版提交；模拟上游/浏览器不冒充真实账号或账单证据。
- 源码按有界批推送，推前读同名远端，推后核对 SHA/tree；并发变化先比较，
  不强推、不 reset/stash/clean、不合并 main、不发布/部署或改生产数据。

## 2026-10-04 首批实现与待验记录

已接线（候选，未封版）：

- 独立服务端 `channel_model_discoveries` 证据表，不存密钥/原始响应；
  GET/POST `/api/channel/model-discovery/:id` 分别读取/刷新，沿现有权限、Origin、
  no-store 和限流。开始序号持久化，旧响应/变更配置拒绝写回；同一完成精确重放
  不重写时间或数据，不同结果拒绝。30分钟仅标显示过期，不自动刷新或改变路由。
- 原 `settings` TEXT 增加可选 `model_routes`，不新增网关；支持 type 1 OpenAI兼容
  与 type 57 Codex，精确旧映射优先，新规则按精确/端点/最长前缀/优先级解析。
  前缀只匹配显式启用的具体公共名，目标是管理员填写的固定ID，不猜后缀。
- 缓存/数据库候选、管理预览与最终发送共用解析；账户可用性沿既有 Codex 门禁。
  预览仍明确不模拟某个 API Key 的准入/冻结价或 affinity 会话状态，不保证下一次
  请求一定选中同一个随机候选。实际请求额外核对原名和最终名的 Key/策略权限。
- 保存新路由使用原始 `routing_config_digest`，事务内锁定核对，旧编辑器拒绝覆盖；
  已存在显式路由时暂停旧自动新增模型，差异继续供人工确认，其他旧渠道行为保留。
- HTTP最终发送前校验最终请求模型，参数覆盖不能偷偷换目标；现有严格预算及
  官网冻结价格的“不合格映射拒绝”保持，不提前扩 beta.6 的收费资格。
- 现有用量日志 admin_info 增加请求名、上游ID、端点、映射原因、渠道及配置摘要；
  这是发送目标/配置证据，不是私有转发商实际底层模型的独立证明。
- 现有渠道编辑页、路由预览和日志详情直接展示；七语言、权限/会话缓存隔离、
  失效/失败/空数据/冲突及原始编辑快照已补。新增真实 Chromium CI 场景。
