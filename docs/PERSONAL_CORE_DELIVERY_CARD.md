## 用户应完成的一个流程

打开个人使用入口 → 看清商业关闭与本人无钱包策略是否生效 → 复用既有 Root 用量策略操作
（旧用户明确选择，不自动迁移）→ 给一个应用 Key 设置所需限制 → 选择有资格的模型/端点 →
调用、看实际 Token/费用/预留及剩余 → 到限拒绝 → 异常保留与恢复可以解释。
关键入口保持少而清楚，常规使用不被支付、订阅或专业账务恢复表单占据。

## 已有基础，不重复实现

- 默认商业 disabled；新安装首个 Root 已有 no_balance=true/revision=1（`controller/setup.go`）；显式用户 `self_use_no_balance` 与 revision 审计/CAS；Root 的用户用量策略 UI。
- 无钱包仍记 Key/用量，当前仅 POST Chat、Responses、Responses compact（无 query）的既有资格。
- 普通 Key 内部额度、模型/上游限制；限定原生文本严格 Token/USD 账本和未知保留。
- Codex 账户/窗口观测与安全阈值；它不是逐 Key 共享百分比账本。
- beta.4–7 路由/资格/策略、beta.8 UI、beta.9 真 Key 聊天已累计发布；RelayKit 独立协议模块已存在。

## 有界工作包与顺序（状态见顶部检查点）

1. **当前最小补丁先封板。** 人工核对不得误开在自动结算记录上；保留严格 Token 的合法恢复入口。
   按 `SETTLEMENT_REVIEW_STATUS_PATCH_CARD.md` 红绿、独审、准确 head CI/三库/浏览器交付新 Draft。
2. **个人入口与限额解释。** 复用现有策略/Key 控件，展示全局资金模式、用户选择、实际生效条件；
   区分内部额度、严格 Token 总量、严格 USD、账户窗口百分比，清楚显示作用对象/单位/支持范围。
   给出拒绝原因与已有设置入口；普通用户只看本人，Root 改动保留审计与显式确认。
   若现有控件已能完成，不另建重复设置。未实现的逐 Key 百分比标明不可用。
   PR #6 已解决的具体差距：用户策略页区分保存偏好/全局模式/实际生效（复用 confirmed+ready），未知不能显示生效；
   Key 编辑中现有“Enter quota in tokens”其实指价格折算内部额度，现已澄清；Unlimited Quota 只解除
   普通额度一层。表格 Gauge 预算入口已加入可见文字，预算摘要区分 Token+USD 可并用与 Codex 阈值互斥。
   保存配置不代表该 Key 所有路由已取得严格资格；最终真实请求仍由服务端判断。
3. **首个结构边界。** 先记录个人准入→Key 预留/结算→用量与可选商业资金的调用图、依赖和合同。
   选择一个实际耦合点提取明确接口/策略解析；保持持久模型、writer、冻结身份与兼容 API。
   用依赖测试阻止个人入口直接调用订单/支付；不以大规模文件搬迁或删测试计算精简成果。
4. **个人场景收口。** 初装与现有用户、零钱包/有限 Key、到限/并发/撤销、失败/未知/重启、
   普通所有者/Root、关闭商业且历史义务仍可恢复，连同七语言窄屏完成一条真实应用路径。

步骤2/3可分文件并行，统一集成；不同时开 Desktop、学习平台、完整文件库或全部协议预算扩展。
参考取舍以 `SUB2API_REFERENCE_AUDIT.md` 固定 commit 为准；其 Simple Mode 软窗口不替代严格硬预算。
