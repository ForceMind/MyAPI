## 实际行为

上游账号页面在明确选择现存 Key 后，按账号与有效原生窗口读取全池快照。桌面并列显示窗口观测与全部 Key，手机顺序排列；保留原 M 和柔和蓝色。该池全部 Key 的配置比例、估计用量、占各自分额比例及待计状态分别显示，含 0% 和已删除身份的历史用量。未分配比例属于配置，不当作用量或上游预留容量。

窗口分解来自真实持久记录：全部 Key 估计 + 周期首次观测占用 + 未归属增长。首次观测不保证等于启用时刻，显式恢复后的参考值单列、不重复相加。缺基线/缺 usage/不一致时保留未知和已有合法值，不画完整分解、不补零、不修写历史。待计与未采样计数可能重叠，页面明确提示。最后处理样本可能失败，保留估计不冒充刚获确认的新用量。

新增 `GET /api/subscription-share/pools/:pool_id/usage` 具备 route/model 双层启用 Root 验证、`no-store`、字段白名单和事务一致性；普通管理员即使可读渠道，也不能读取全池。只读接口不刷新投影、不建 gate、不迁移表、不改变分额或计费算法。完整合同见 [分额合同补充](SUBSCRIPTION_KEY_SHARE_CONTRACT_20261014.md#全池只读观测补充2026-10-16)。

Key 高级维护保留已有功能，并补上会话边界：卸载或用户/角色/session 改变后停止旧批量任务的后续写入、迟到秘密缓存与通知、聊天/导出跳转。相关请求禁止自动认证重放，避免旧 401 借新会话执行；其它现有客户端调用的默认刷新行为保持。请求失败后由当前会话明确反馈，不自动重试写入。

个人资料、调用记录和原有分额编辑继续沿用第一批已验证行为：完整回答缺 usage 仍显示请求成功、Token 未知；主流程不显示金额余额；比例调整保留估计用量，0% 停止后续请求，近似计量不预留容量。
