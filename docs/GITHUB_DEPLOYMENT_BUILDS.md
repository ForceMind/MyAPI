# GitHub 构建与服务器部署

用户于 2026-09-09 授权部署 0.1.4，并要求把后续构建移到 GitHub Actions。

`deployment-artifact.yml` 在 `codex/deploy-*` 分支源码推送时自动构建，也支持手动运行。GitHub 执行 Bun 安装、类型检查、前端测试/构建、受影响后端测试、relaykit 独立构建和 Linux amd64 静态二进制构建。前端嵌入二进制；制品带版本、完整来源提交和 SHA256 校验文件。Actions 只读仓库权限，不配置服务器 SSH 凭据、不自动切生产、不发布 Release/GHCR。私有仓库制品保留三天，不启用额外 Actions 构建缓存。

部署门槛：同一完整提交的 `CI` 和 `Build deployment artifact` 均须成功。部署分支的完整 CI 使用 `gh workflow run ci.yml --ref <部署分支>` 启动，覆盖数据库矩阵、路由并发、浏览器回归和完整后端验证。制品上传成功本身不表示允许切换生产。

服务器流程：按完整提交找到两个成功运行，下载对应制品，核对提交/版本/校验和；以现有运行镜像为基础只替换二进制（无编译）；优雅停止单个服务并备份 SQLite/Compose，核对备份完整性后切换镜像。验证容器健康、版本、HTTPS 静态资源、数据库完整性、配置保持和管理接口未登录拒绝。保留上一个镜像用于回滚，不自动覆盖运行数据库。

本次使用独立部署分支，不直接修改受保护 main。后续源代码仍须先推到 GitHub 才能在那里构建；工作流合入 main 后可从 Actions 界面手动选择任意已推送分支。仅下载制品和 Docker 运行镜像会占服务器磁盘；Go/Bun 编译 CPU 与缓存由 GitHub runner 承担。

每次完成部署删除下载包、临时二进制与本次构建缓存，保留运行镜像、上一版回滚镜像与数据库备份。不要使用全局 Docker prune 删除无关项目资源。

发行边界：此分支的 0.1.4 是私有服务器部署候选，没有发布同名 GHCR 镜像。CLI/新安装模板的 0.1.4 默认地址仅供后续正式发行使用，当前不能把模板当作已发布镜像安装入口；本次生产只使用本地封装镜像，不读取该模板。正式发行前须确认 Full/LAN 镜像存在并统一 Compose 无环境文件时的默认版本。
