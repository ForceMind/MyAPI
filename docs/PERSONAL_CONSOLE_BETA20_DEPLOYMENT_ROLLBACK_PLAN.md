## 全新安装路径

经后续授权后，在独立目录准备全新数据库、日志和配置，选择 Full 或 LAN，与现有实例使用不同端口和挂载。保留 loopback 默认绑定、CPU/内存限制、同源 URL 与 Cookie 约束；对外暴露范围必须另行明确。已有目录、库或 Redis 不能冒充“全新”。

全新无缓存安装使用已经明确审核的 `BATCH_UPDATE_ENABLED=false` 和 `MYAPI_ACCOUNTING_CONFIG_VERSION=1`；这两个值不是迁移已有实例的通用办法。新的 quota identity keyring 只适用于新的库；已有 keyring、SESSION_SECRET 和数据身份必须保留，不打印到报告或提交 Git。

现有部署模板不提供 Redis，也不完整表达已有集群的 authoritative 配置。两种 writer 的测试实例分别从全新库建立，不能将 CI 中的模式选择步骤复制给旧实例。只有通过未来正式发行门禁后，才选择对应发行版固定 digest，执行安装器并检查健康、登录、可见版本、原始 M、手机导航、个人主流程及访问边界。

## 已有实例的升级路径

1. 独立授权只读核对目标状态和冻结范围。备份必须涵盖数据库、WAL/必要 sidecar、配置、稳定 identity keyring、原镜像身份及其他持久文件，置于受控目录；报告只保存允许公开的摘要和验证结论。`.env` 备份不是数据库备份。
2. 根据实际数据库类型采用一致性备份工具；SQLite 不逐文件复制运行中的生产库，不漏 WAL。所有写入节点和在途请求要有明确停止/排空方案。Redis 义务不得被忽略或通过改 batch=false 丢弃。
3. 在另获授权的副本环境验证准确目标版本及原备份恢复，断开真实上游出口，保持真实配置语义；未证明历史执行证据时，应接受启动拒绝并停止升级，不能修改历史以获取绿灯。
4. 可先对**新建合成演练项目**执行以下 CLI dry-run；它只检查部署文件/环境/资源，不访问 Docker、镜像仓库，不创建备份，也不证明已有实例账务资格：

   ```bash
   node /root/myapi/cli/myapi.mjs upgrade \
     --project-dir /tmp/myapi-approved-rehearsal \
     --version 0.2.0-beta.20 --dry-run --json
   ```

   本文示例目录必须由操作者单独准备为合成项目；不要替换成生产目录并按本文执行。实际升级命令需等制品发布、目标资格和部署授权齐备后另行列出。
5. 后续获准部署时，先保留升级前完整原始备份及对应旧镜像，核对目标 digest 和副本结果，再于维护窗口切换。健康检查只是一项检查；必须核对原有用户/Key/渠道身份、权限、计数、日志、版本、手机/桌面流程及队列状态后才恢复接入。

当前 CLI `upgrade` 目标是按版本固定的 GHCR 镜像，不接受本批临时 smoke tar 冒充正式升级源。`--pin-digest` 和签名检查仅在未来真实拉取阶段执行；dry-run 不验证签名或远端镜像存在性。

## 失败与回滚边界

| 失败位置 | 处理方式 |
| --- | --- |
| 目标启动前，拉取/签名/digest 等失败 | 现有 CLI 恢复原环境与旧服务，并报告恢复失败；仍需确认原服务健康 |
| 已尝试目标启动，包括超时/结果未知 | 保留目标现场和配置；不自动切回旧镜像或重启旧部署，先核验数据是否变化 |
| 历史执行门禁明确拒绝 | 停止升级，保留原因、身份及拒绝前后证据；不改 writer、账务标记或权限放行 |
| 需要恢复数据 | 另行授权后，从升级前原始备份的独立工作副本恢复数据库/配置，再配套原镜像验收；旧程序不读取已升级数据库 |
| 已发生轮换或迁移 | 恢复数据库可能重新激活旧秘密或旧归属；不能只凭容器健康恢复接入，必须单独盘点客户端凭据/归属后续处理 |

备份恢复只恢复备份时点的数据。备份后的新增 Key、轮换秘密、归属变更、已外发请求及上游实际使用不能由数据库恢复撤销。凭据秘密不能从单次展示回执重放恢复；未知结果应使用既有 operation/receipt 查询，不能再次提交新操作冒充恢复。目标服务失联时保持访问关闭，由维护者依据证据决定继续修复或恢复，不能自动选更宽 Key。

恢复验收至少核对：数据库完整性、用户/Key/渠道身份及状态、Key 模型范围/到期/限额、计数与日志/结算证据、writer/worker/Redis 状态、备份未变、无上游请求重放、登录及关键页面。当前隔离测试覆盖的字段和未验证部分按最终报告列出，不能据此处理被冻结的真实历史项。
