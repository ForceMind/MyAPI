## 实施、所有权和资源

沿用当前持久 Goal。主代理负责工作流、集成、新执行/交付/部署回滚文档、准确来源和证据索引、现有功能分支及 Draft PR #17 同步；base 保持 `codex/personal-core-20261014`。`stage1_runtime_tests`（工具实际支持 `gpt-5.6-sol/high`）只写 `tools/runtime/` 并补相关合同测试；`stage1_qualification_audit`（`gpt-5.6-sol/ultra`）只读规划与独立审查，不参与实现。最多三个活跃角色，不递归、不争写。

1. 核对现有镜像来源、安装、空历史迁移、含历史拒绝与原始备份恢复合同，找出具体证据缺口；复用已有测试，不扩大历史操作范围。
2. 补齐验收缺口与安全报告，并在本机运行轻量定向测试/语法检查。重型构建、三库、Chromium 和 Docker 复用现有 GitHub Actions；不安装本地浏览器或前端依赖。
3. 在准确功能分支提交上手动运行现有 Docker smoke，启用 personal；Full/LAN 均生成不可变测试 bundle，Full 分别运行 legacy/authoritative 个人流程，另验 LAN 源码安装及合成 handoff/恢复。所有镜像 `push:false`，不调用发布工作流。
4. 下载并核对源 SHA、tree、manifest/tar SHA256、镜像 ID、构建版本和测试报告，保留桌面/手机原图。独立审查后形成部署前置条件、回滚边界和待授权步骤；同步现有分支/Draft PR，交付实际隔离运行页面及证据。

## 验收与停止条件

完成以准确源码作业终态、不可变 Full/LAN 制品、安装/恢复合同、两 writer 实际 Go/浏览器流程和独立审查为依据。原图按字节归档，生成的索引与原始报告区分。制品是未发布的 CI 测试镜像，不冒充公开可拉取发行版。

部署方案必须区分全新安装和已有实例；未知 writer、未处理历史/在途账务、旧 worker、缺备份/恢复验证或轮换证据时保留阻断。原镜像只能配套升级前原始备份恢复，不能直接读取已升级数据库；服务恢复不等于恢复已外发 Key 的秘密。本阶段不执行方案中的生产命令。

测试失败先记录具体来源和错误，做范围内修复并定向复验；缺真实账号、生产快照或部署授权时仅记录下一阶段门禁，不使用真实资源补验。必需隔离验证未通过或独审未完成时保持待验证。
