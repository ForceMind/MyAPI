# MyAPI 平台重构方案与现状核查

状态：P1–P4平台首版已交付；维护者已直接授权当前S1迭代补齐调用记录的缓存命中率和Token统计。仅沿统计闭环实施、构建及隔离验收，不部署。

本轮目标：按完整 AI 网关管理平台重新设计首页、信息架构、业务流程和 PC / 移动两套界面，解决“页面简化后管理能力丢失、流程割裂”的问题。现有成熟后端、请求转发、日志、权限、Key 身份和真实数据继续保留。

本轮起点：分支 `codex/subscription-key-share-20261014`，HEAD `c6641b9d01e04c5ad3ff0434e613612a21e0b10e`；此前本机 beta.21 部署完成，见[部署记录](evidence/personal-console-beta21-local-deployment-20261020/README.md)。本轮仅对本机公开 `/api/status` 与 `/api/home_page_content` 各读一次，未登录、读取真实凭据、直接访问生产数据库、调用供应商业务接口或重部署。已有 Draft PR #17 / base 保持。

## 2. 产品定义与边界

MyAPI 的核心用途是管理上游连接、约束调用访问、查看真实请求、诊断错误并维护运行环境。自用代表由本人管理、其他人只用 Key；界面需要让一个管理者掌握完整平台。

保留 MyAPI 名称、原 M 标识和既有蓝色识别。重新设计内容密度、布局、导航和交互，不把原来五页的裁剪结果继续作为完整性上限。保留成熟功能，避免重新实现另一套网关、认证或日志后端。

版型、资金模式与权限分开：Full / Lite 决定经核实的能力矩阵；资金禁用只影响金额、钱包及相关商业动作；登录角色和已有权限决定能读写的对象；设备宽度决定页面呈现。恢复管理入口不放宽后端权限，也不启用收费、用户注册或资金功能。

以下边界保持：

- 个人日常页面不展示金额余额。账号订阅窗口、Key 分额、Token 预算分别说明，不能混为货币余额。
- 完整回答缺 usage 仍为请求成功，Token 未知；统计须保留未知数量与覆盖范围，不把未知补 0。
- 分额按可信账号原生订阅窗口近似分配，保留误差说明与重置证据，不伪造精确逐 Key 上游使用量。
- 原用户、Token ID、API Key、账号身份及权限契约保持；轮换/跨账号迁移继续按 authoritative、backfill、schema、未决义务和兼容性门槛阻断。
- 历史账务及 5 条既存 usage_unknown 不修改、不补扣、不退款、不改 applied 或 writer 放行。
- 不包含此前未批准的 SIWC 新协议，也不因为本轮 UI 重构自动刷新共享 Codex 会话或执行真实供应商试验。
- beta.21 正式实例保持服务，本轮重构先在隔离环境交付；下一版本实际部署需要准确制品和目标的单独批准。

## 3. 业务对象与完整工作流

### 3.1 对象关系

| 对象 | 用户需要理解的含义 | 现有实现处理原则 |
| --- | --- | --- |
| 上游账号 / 凭据 | 连接哪个供应商、凭据类型、认证状态；订阅账号可能提供原生窗口 | 使用已有可信账号标识；不能按邮箱、名字或 UI 猜测把多个账号合并 |
| 渠道 / 路由 | 哪种接口、哪些模型、如何选择上游及处理失败 | 保留 channels、abilities、模型映射、优先级和现有路由语义；与账号窗口建立可见关联 |
| 模型 | 已配置模型、协议、可路由的渠道和访问限制 | 区分“已配置”“有近期验证证据”“不支持”，不在打开页面时自动向上游测试 |
| API Key | 发给哪个客户端或使用者、模型范围、限额、有效期及访问策略 | 沿用已有 Token 身份及服务端限制，不因为页面简化扩大 Key 权限 |
| 请求 / 尝试 | 一个客户端请求经过哪些路由与上游尝试、如何结束 | 请求与上游尝试分层；一 request_id 可关联多条日志，不假设所有日志行一对一 |
| 内容、任务、审计 | 脱敏请求响应与 SSE；异步生成进度；登录和管理动作 | 保留各自数据来源、权限和保留策略，并由关联入口串起 |

账号与渠道的关联先做基于现有可信身份的展示，不迁移账号数据模型、不重写身份。无法建立可信关联时保持独立并说明未确认。

### 3.2 必须完成的用户旅程

1. 进入站点 → 登录 → 总览，直接看到可管理的连接、访问和近期请求；已登录访问 `/` 可到工作台，原深链接继续可用。
2. 发现账号/采样异常 → 定位具体账号与窗口 → 查看最近成功观测、最近失败分类和时间 → 到已有连接维护入口；不能只让用户面对“未知”。
3. 管理 Key → 查看允许模型、访问限制、所属分额与使用记录 → 修改已有许可策略 → 确认实际结果；资格不足的轮换/迁移保留原因和可读证据，不给出绕过建议。
4. 查一次请求 → 按 Key/模型/时间/请求 ID 定位 → 查看结果与计时、渠道、路由尝试 → 进入同请求脱敏内容/SSE → 回到原筛选与列表位置。
5. 查失败/异步任务 → 区分 API 请求结果、任务处理结果、用量可信度及账务状态 → 追踪对应日志和后台任务；查看不触发重试或重新生成。
6. 维护系统 → 查看版本、实例和后台任务 → 进入相应安全/路由/日志设置；读取失败有恢复入口，写操作沿用权限、确认和审计。

| 分区 | 主入口与子功能 | 复用的主要路径 |
| --- | --- | --- |

调用记录不是只有两类卡片。日常请求视图默认聚焦调用，审计、错误、退款等原有日志类型由明确的分区/过滤器提供；现有财务冻结的只读历史沿用权限，不重新打开资金业务。内容日志未开启、已过保留期或没有匹配记录时明确说明，不自动开启采集或伪造旧正文。

## 6. 总览与窗口错误的具体调整

总览回答：现在配置了哪些连接，近期请求表现如何，哪些问题需要处理，下一步在哪里做。默认不把每个账号的主/次窗口都变成一组大卡片。

基础摘要仅展示有明确定义与数据来源的请求数、成功/失败结果、延迟、启用连接及 Key；新实例没请求时显示空态，不合成成功率。Token 汇总说明已知覆盖率/未知次数。模型与路由分析复用既有模块，按需进入详细看板。

窗口展示分离以下事实：供应商/账号与窗口名、最近有效观测数值及时间、最新采样结果、是否过期、重置是否有可信证据。没有窗口能力与采样失败分开；401/403 等错误不能仅凭代码自动解释为额度耗尽或要求重登录。错误涉及同一账号多个窗口时归并待办数量。

当前 `ChannelQuotaChangeItem` 没有直接提供完整错误码和最后成功观测的专门字段。实施先核实已有 snapshot/history/analysis 数据；不足时只提出必要的只读、脱敏接口补充，单独列准确字段和权限，不为 UI 扫描私有原始响应或改变采样频率。

默认打开页面、切标签和重新读缓存不新增供应商 HTTP；需要真实上游查询的动作必须有清楚含义并沿用现有控制，不伪装成无副作用的刷新。

## 7. 日志恢复和排错合同

复用已有普通日志、内容日志、任务日志和系统任务接口。管理员与本人视图按已有角色/鉴权调用对应接口；资金禁用不能令管理员自动丢失诊断权限。个人页面隐藏金额列，但保留请求和排错信息。

| 数据 | 当前来源 | 新 UI 处理 |
| --- | --- | --- |
| 调用与审计 | `/api/log/`、`/api/log/self` 与既有统计接口 | 服务端过滤与分页；时间、Key、模型、渠道、类型、Request ID、上游 Request ID 依现有合同提供 |
| 内容与 SSE | `/api/full-content-logs`、`/:request_id` | 从请求详情关联、脱敏显示、按需读取；保留大小/数量/截断边界 |
| 绘图/异步任务 | 既有 mj/task 查询接口 | 状态、进度、失败原因及关联请求；查看不触发重试 |
| 后台与实例 | `/api/system-task/*`、`/api/system-info/*` | 运行/失败证据、时间和可读诊断；不自动执行清理、删除实例或退款 |

细节必须有字段依据：业务完成、HTTP 状态、用量可信度、结算状态分别展示；没有存 HTTP 状态时显示缺失，并在内容记录存在时关联真实字段，不能写死 Unknown，也不能反推 200。原记录缺失/截断、功能未启用和权限不足有不同空态。

SSE 查看限于现有持久内容、事件文本和分片统计等可证明信息，不承诺新增实时流监视或上游重放。读取历史流式内容不会重新调用模型。

请求结果筛选不允许只筛当前 20 条而宣称筛了全部。先提供服务端已经支持的准确“日志类型”等条件；如需要新增跨页结果筛选，须先核对可查询字段及历史语义，不为方便筛选回填历史账务或引入单库 JSON SQL。未实现的全局条件不能伪装为已支持。

## 10. 验收与停止条件

### 功能与交互

- 所有已存在且有权限的核心功能都能由导航到达；手机也能进入内容日志、任务日志、系统信息及设置；禁用或版型不支持有准确原因。
- 管理员完整查询与仅本人范围均受后端权限保护，资金禁用不再替代功能裁剪；不能从低权限会话短暂看到管理员内容。
- 筛选作用域、分页总数、时间单位与时区清楚；返回、刷新、书签及复制请求 ID 后上下文正确。
- 请求结果与 usage/结算分离，完整回答缺 usage 仍成功；历史未知不补 0，不修改账务。
- 正文、JSON/SSE 与错误信息脱敏且有大小边界；详情关闭不泄露状态到下一条请求或下一次会话。
- 单条异常能定位账号/渠道/请求，提供清楚下一步；不会在各页重复撑出大横幅或用视觉变化掩盖真实错误。

### 双端与实际页面

- 覆盖 PC 1280/1440、手机 320/390、768/1024 临界宽度、长中文/英文标签与高缩放。
- 列表、详情、筛选、编辑、返回、弹层、焦点恢复和键盘操作实际验证；不以大屏缩窄截图代替移动端流程。
- 页面无横向裁切、按钮和底部操作不遮正文；只有代码/原始内容等必要区域允许独立水平滚动。
