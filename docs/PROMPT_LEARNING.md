# My API 提示词学习与版本中心（S5-P）

> 文档状态：P0 产品、权限与实现合同；另有未接线的 P1a/P1b 纯准入、脱敏与指纹内核。
> P1 的采集、持久化、用户隔离、轮次识别、预览和保留仍未实现。
>
> 本文定义的能力默认关闭；本文件不授权读取真实日志、外发内容、调用付费模型、读取或写入 Codex 指令文件，也不授权修改宿主凭据。

## 1. 目标与非目标

S5-P「提示词学习与版本中心」帮助**已明确启用并授权**的用户，从自己主动提出的需求中形成可审阅、可复用的 Codex 自定义指令文档。它覆盖 Full 服务器、Lite 服务器、个人电脑 Lite 和 Desktop；功能版、安装形态与访问模式不改变其数据授权边界。

首版必须支持：

1. 受控增量样本的分析与草稿生成；
2. 经单独授权读取的现有 Codex 自定义指令作为生成基线；
3. 人工编辑、输入修改要求后的模型再生成、版本历史、来源、差异、导出与回滚；
4. 对经单独授权的目标文件进行预览、备份、原子应用和回滚；
5. 时间与新增有效请求数两种触发方式、预算/限额、失败恢复和审计。

它不是通用的渠道 `SystemPrompt` 注入器，也不改变现有 relay 的协议、计费或重试语义。现有 Full Content 日志是观测资料而非本模块的权威数据源；不得把全部 `role=user`、助手输出、工具结果或原始 JSONL 批量交给分析模型。

以下行为永远不在默认范围内：自动扫描主目录、`CODEX_HOME`、`auth.json`、Keychain、浏览器或其他凭据库；执行日志中的指令；自动发布/自动覆盖 Codex 文件；为分析模型开启工具、文件执行或任意网络权限；跨用户学习或管理员越权外发。

### 1.1 当前 P1a/P1b 纯内核边界（已完成本地子范围）

`service/promptlearning/` 现有一个未被任何运行路径调用的 Go 纯内核。P1a 只接受包内构造的候选，拒绝客户端伪称的内部来源、历史/助手/工具/附件/响应/自动任务内容；对可审阅文本做大小、UTF-8、控制字符与 Unicode 格式字符边界检查、两层脱敏，以及按 policy/owner/opaque subject scope 隔离的 HMAC transport/semantic/occurrence 指纹。

P1b 新增包私有的 `serverObservedLiveTurn` 准入边界：未来认证后的服务器 ingress 才能构造完整、有界的观测 turn。它要求每段均为 server-marked 且无客户端 role/origin 声明，并且恰有一个 `new_user_text`；明确标记的 history、system、developer、assistant、tool、attachment、response、internal 与 automatic analysis 段可以随 turn 一同出现，但永远不进入返回正文、脱敏摘要或任何指纹。缺少/多个新用户段、未知/未标记段、客户端声明和不完整 provenance 均 fail closed。它不能从 Full Content JSONL、客户端 request JSON 或 `role=user` 字段构造可信来源。

`hmac-sha256-v2` / `occurrence-v2` 只用稳定 conversation/turn receipt 形成 live logical identity；transport 也不因物理 node、source epoch 或 HTTP request observation 改变。另有独立的 `observation-v1` HMAC 绑定 scope、node、epoch、conversation、turn、request observation 与**规范化后的 eligible payload**，供未来审计关联，而不改变 logical replay 语义。来源候选、判定结果和指纹均不是对外可构造/持久化的 API。

它不读取日志、数据库、文件或凭据，不含 HTTP 路由、worker、模型调用、调度、API、迁移或外部调用者；默认关闭仍等于零采集和零调用。未来的认证 ingress 必须在该包内从服务器观测的身份/会话/轮次记录构造候选，且由主库唯一约束先裁定 occurrence 的 new/replay/conflict，再使用 transport/observation receipt 作冲突与审计关联；纯内核不能自行证明来源可信，也不能宣称请求已经计数。

本地合成测试和独立只读审查已覆盖 fail-closed 的 JSON/YAML/indentless sequence、公共 marker、敏感内容、来源边界与指纹域，以及跨 node/epoch/request-observation 的 replay、同 turn 异载荷 conflict、scope 三段隔离、retired-key alias、完整混合 turn、拒绝零泄漏和非规范等价载荷。上下文敏感标签以 Unicode rune 词边界识别，中文、阿拉伯文等普通词内的 ASCII 后缀不会误触发，而 Unicode 标点后的真实 `token=` 与既有 Bearer/URL/JWT/API key/邮件/电话/高熵规则仍遮盖；最新单核/768MiB 定向 test/vet 与两轮独立复审均通过。D13 的 scope、加密和真实费用选择仍是后续实现门禁。

## 2. 三层授权与数据边界

读取、外发、写入必须是三个独立、可撤销、带审计的授权：

| 行为 | 最小授权内容 | 禁止的推论 |
| --- | --- | --- |
| 学习样本 | 用户、项目、Key 范围；启用时间；可选历史时间段 | 管理员能查看日志不等于可把其他用户日志用于学习或外发 |
| 指令读取 | 指定机器、账号、文件、作用域及一次/持续授权 | 凭据导入权限不等于文件读取权限；不得扫描整个主目录 |
| 模型分析 | 冻结的脱敏样本集、指定渠道和具体模型、预算 | 不可在模型/渠道不可用时静默换渠道、模型或凭据 |
| 文件应用 | 指定版本、目标文件、机器/账号、有效期及操作者确认 | “已生成草稿”或“已读文件”不等于允许写入 |

每条授权记录 `subject_scope`、目标、签发者、签发时间、过期/撤销状态、generation 与审计原因。撤销后，新的采集、调度、读取、外发和写入立即拒绝；已向模型提交的请求只能如实标为已发送、结果未知或已完成，不能声称撤回费用。

默认仅处理授权开启后的数据。历史回溯必须让用户选择范围、看到缺失区间和预估样本量；日志已轮转、未保存或来源无法证明时只能显示缺失或低置信候选，不能补造出现次数。

## 3. 学习样本合同

### 3.1 有效用户请求

一个“新增有效用户请求”必须同时满足：

- 来自可信的请求/会话/轮次来源标识，而不是仅凭客户端声明 `role=user`；
- 是本轮新增的用户输入，而不是请求中反复携带的历史会话；
- 不是传输重试、重复上传、内部任务、自动分析、助手输出、工具结果、附件、图片、凭据或响应正文；
- 在授权用户、项目和 Key 范围内，且未被删除或排除；
- 经稳定指纹去重后仍是独立用户再次提出的需求。

旧日志没有可信会话或轮次信息时，可作为标有 `low_confidence` 的人工候选，但不得计入“独立出现次数”或自动触发阈值。分析任务及其模型请求必须带可信内部来源标记，永远排除出本模块的样本和触发计数，避免自我循环。

### 3.2 派生样本而非原始日志副本

建议新增主库领域记录：

| 记录 | 最小内容 | 不应保存 |
| --- | --- | --- |
| `prompt_learning_policy` | 开关、范围、触发、预算、保留规则、generation | 原始聊天正文 |
| `prompt_learning_watermark` | 节点来源、增量游标、最后确认的范围和时间 | 伪造的全站覆盖结论 |
| `prompt_learning_sample` | 脱敏后需求文本、来源引用、可信度、去重指纹、排除/删除状态 | 完整请求、附件、工具/响应正文、凭据 |
| `prompt_learning_run` / `attempt` | 冻结样本范围、基线版本、模型/模板、预算快照、lease、状态和错误 | 上游完整敏感响应 |
| `prompt_instruction_version` | 不可变正文、父版本、内容 hash、来源摘要、操作者、生成信息 | 未经批准的原始聊天证据 |
| `prompt_instruction_application` | 目标授权、备份引用、期望文件版本、结果和回滚关系 | 凭据或未授权文件内容 |

原始 Full Content 日志继续沿用原有开关、脱敏与保留策略；S5-P 不修改它们。采样先提取允许的用户需求文本，再做第二层内容脱敏、大小限制和人工预览。字段名脱敏不足以识别正文中的密码、密钥和个人信息，因此第二层必须有文本敏感模式、上下文检测、可见替换标记与人工排除。测试只用合成日志和隔离目录。

多节点部署需要可靠的节点来源、增量游标、去重键和汇聚协议；主节点只扫描自身本地文件时必须显示覆盖范围，而不能宣称已覆盖全站。

## 4. 触发、调度与费用合同

模块默认关闭。启用后，可独立启用时间触发和请求数触发：

- 默认时间计划为 `Asia/Shanghai` 每日 03:00；用户可选时区、每日/每周时间或固定间隔；
- 按累计 `N` 个新增有效用户请求触发；用户请求数与模型调用数分开计量；
- 两种触发按 `any`（任一满足）或 `all`（同时满足）组合；同一水位同时命中时只创建一个 run；
- 支持立即运行、暂停与取消待执行任务。关闭会停止新增采集和调度、取消未开始任务，并让运行中任务停止后续调用；
- 没有新增可用样本则记录 `skipped_no_new_data`，不调用模型；
- 休眠、关机或服务离线后只合并补跑最近一个应执行窗口，绝不连续补跑全部历史时间点；
- policy 明确定义冷却期、统计窗口、最大样本量、分析水位、失败退避、租约、幂等 command ID 和保留期。

状态机至少区分：

```text
pending → leased → preparing → submitted → succeeded
                    ↘ skipped_no_new_data | cancelled | failed
submitted → submission_unknown → outcome_unknown | manually_resolved
```

同一冻结输入、基线版本和 command ID 的重试不得重复创建版本、重复累计证据或不受限重复收费。网络结果不明、上游超时或进程崩溃进入未知态并保留费用可能已发生的事实；不得无上限重试或假称未收费。

分析调用必须走正常渠道、权限、计费、限额和审计路径，使用指定渠道与具体模型。默认优先 GPT-6 仅是产品选择优先级，实际 API 模型 ID 由已配置且可用的渠道决定；无可用模型、额度不足、预算耗尽或渠道失效必须显示准确状态，不静默切换。每轮冻结并记录样本量、输入/输出上限、调用次数、token、费用、每日预算和模板版本。

分析模型的执行环境默认无工具、无文件执行、无任意网络访问；日志内文本始终是待分析数据，不执行其命令，也不据此扩大权限。

## 5. 提炼、版本与冲突合同

每轮输出必须将候选分为：长期偏好、多次独立需求、明确纠正、明确禁止、项目专属规则、一次性要求、已被新要求取代的旧规则，以及相互矛盾或证据不足的候选。每条候选至少显示适用范围、来源引用、独立出现次数、时间范围、可信度、与现有规则的冲突，以及 `pending`、`confirmed`、`excluded`、`locked` 状态。

频率本身不能把规则提升为全局强制规则；项目规则不能套用到所有项目。确认或锁定规则不能被后续自动总结静默删除，自动结果只能提出替代/冲突候选。

一个版本由两份内容组成：

1. **可应用指令正文**：精简、可直接使用的自定义指令文档；默认不包含原始聊天、敏感内容或全部证据。
2. **审阅资料**：来源、解释、冲突、排除、授权、模型、token、费用与审阅结论，仅供受权人查看。

自动生成、人工编辑和模型再生成均创建不可变新版本。版本记录父版本、基线版本、内容 hash、操作者、生成渠道/模型、模板版本、冻结来源范围和费用。比较、导出 Markdown、从历史版本继续编辑、分支候选、回滚与重新应用都基于该不可变版本。

生成时冻结样本范围和基线版本。期间若有人编辑，旧 run 的结果不能覆盖新编辑：保留为候选分支或提示冲突。失败不破坏已存在版本，也不把水位推进为成功分析。

## 6. Codex 自定义指令集成

这里的“Codex 系统提示词”仅指用户可管理的自定义指令来源，例如全局或项目级 `AGENTS.md`、经当前 Codex 版本验证支持的其他指令来源；不读取或修改模型内置、隐藏系统指令。

在实际集成前，必须在**用户授权的目标机器和隔离目录**验证：`CODEX_HOME` 的实际位置、`AGENTS.override.md` 等覆盖优先级、全局/项目作用域、长度限制、加载机制和写入何时对新会话生效。文件写入成功不能表示当前会话已加载。

“应用到 Codex”必须是人工确认动作：

1. 显示目标机器、账号、规范化路径、作用域、当前文件摘要、目标版本与差异；
2. 核对未撤销授权、文件读取后的版本/mtime/hash、路径根、权限与目标文件类型；
3. 拒绝路径穿越、符号链接绕过、硬链接/不安全替换和任意文件写入；
4. 写入前生成权限受限备份，使用安全临时文件和原子替换，写后重新读取校验内容/权限；
5. 外部修改、权限不足、冲突或写入失败时停止覆盖，保留双方内容和可靠恢复路径；
6. 保存应用回执、备份引用和回滚关系。定时任务只生成草稿，永不自动应用。

服务器原生版仅可处理服务器绑定账号明确授权的文件；容器必须经受限宿主桥接，不能挂载整个主目录；Desktop 使用原生文件选择与受限桌面接口；LAN 浏览器不能直接读写访问者电脑文件，只能使用该电脑的本地组件或导入/导出。公网访问 My API 不赋予任何宿主文件或 Codex 权限。

## 7. 产品、安装与更新的交叉合同

S5-P 支持 Full、Lite 和 Desktop，但其可运行性取决于服务在线、模块开关、有效授权和预算，不取决于桌面窗口是否打开。Lite 服务器不得因功能版被一律禁止指令文件集成；物理文件权限仍按目标机器、安装形态和明确授权判定。

升级、产品形态切换和备份恢复必须保留 S5-P 的 policy、派生样本、版本、审阅资料、watermark、任务状态、授权审计和 Codex 应用备份。更新开始时，worker 停止提交新的模型请求；已提交请求保持其真实未知/完成状态。升级不会自动重新读取、应用、覆盖或删除 Codex 指令文件。

完整的发行、数据目录、更新、回退和产品切换合同见 [发行制品与安装更新合同](RELEASE_MANIFEST.md)。

## 8. API、界面与实施边界

未来控制面以独立的 `/api/prompt-learning/...` 路由、专用 service/model 和持久任务表实现，不复用 `system_task` 作为全文任务队列，也不把现有全局 Casbin 资源误当项目/用户级内容授权。所有写操作使用稳定 command ID 和 `expected_generation`；读写均在主库用户隔离与授权 generation 下裁决。

S6 必须提供：启用/范围/保留与预算设置、样本预览/排除/删除、计划与运行历史、模型/费用状态、候选规则审阅、编辑/再生成、差异/历史/导出、授权管理、应用/回滚和安装形态限制说明。加载、空数据、失败、未知结果、冲突、权限不足、撤权和预算耗尽均有独立状态。全部用户可见 UI 文案覆盖 `en`、`zh`、`zh-TW`、`fr`、`ja`、`ru`、`vi`；安装教程至少有经验证的中文和英文版本。

建议文件所有权按阶段划分：数据模型与迁移单写者；服务/控制器单写者；relay 热点文件只在 B2/B3/C03b 稳定后串行接入；S5-P worker 独立；前端 `web/src/features/prompt-learning/` 独立；共享导航、迁移和测试由主代理统一调度。不得并行争写共享迁移或启动重型构建。

## 9. 分阶段、依赖与验收

| 阶段 | 交付 | 主要依赖 |
| --- | --- | --- |
| P0 | 本文、权限矩阵、数据/页面/验收合同 | 无；仅设计与合成 fixture |
| P1a（已完成本地纯内核子范围） | 无外部依赖的候选准入、二层脱敏、长度边界与 v2 HMAC 指纹；同一可信 conversation/turn 跨物理节点/普通重启保持 replay，物理 provenance 不进入 logical dedupe；不接真实 ingress 或存储 | 仅合成测试；不替代 P1 |
| P1b（已完成本地纯内核子范围） | package-private 完整 server-observed turn 准入、明确排除段、独立 observation-v1 provenance HMAC 与拒绝零泄漏；不接 Full Content、真实 ingress 或存储 | 仅合成测试；未来必须由认证服务器 ingress 构造，不能绕过 P1a/P1b |
| P1 | 增量采集、用户隔离、轮次识别、去重、二层脱敏、预览/保留 | Full Content 边界与用户授权模型稳定；必须消费 P1a/P1b 而非绕过它 |
| P2 | 调度、预算、模型调用、版本生成、未知态/失败恢复 | B3 原子账务与 C03b 权威余额/receipt 后才可启用付费自动调用 |
| P3 | 编辑、再生成、差异、历史、导出及完整 UI | P1/P2 API 与 S6 设计系统 |
