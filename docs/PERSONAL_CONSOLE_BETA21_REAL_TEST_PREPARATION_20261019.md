## 离线预置步骤（批准后执行）

“离线”指禁止供应商业务出站；本机 loopback 初始化与登录不在 24 次上游 HTTP 预算内。只有被明确识别的新目录、新库、新进程属于写入范围。以下仍是待批准的真实预置方案；已实现脚本仅验证合成流程，不读取真实凭据，五个业务分类预算均为 0，不能当作下面真实流程的执行入口。

1. **核对来源和环境。** 回读分支、HEAD、差异、受保护文件摘要和 Goal。固定准确候选源码或与候选匹配的制品及 SHA256、版型和平台；不使用 beta.20 Docker bundle。检查端口、进程、build revision 和实际持久目录，不复用旧 `/tmp` 服务。需要构建时另按既有资源规则安排，不把归档 HEAD 称为被构建候选。
2. **建立无外部出口的独立进程。** 只监听批准的 literal loopback 地址，使用全新 SQLite 主库/日志存储；不继承真实 SQL/Redis 连接、生产配置或挂载。启动即设置 `MYAPI_UPSTREAM_ACCEPTANCE_ENABLED=true`，保持后台采样、自动 refresh 和 Codex 模型更新暂停。通过环境实际支持的出口控制禁止外部连接并核验；没有该能力时停止预置，不把 run 栅栏称为全进程防火墙。此阶段不接触真实凭据。
3. **自动生成本地临时 Root。** 在内存中用密码学随机源生成用户名和密码：用户名可用`at`加10个随机hex字符（共12字符），密码可用15个随机字节的base64url编码（20字符）。使用本次独立会话，不借用生产密钥。先`GET /api/setup`，只有`status=false`且`root_init=false`才`POST /api/setup`，再正常`POST /api/user/login`核对Root。不要求人工填表，不签假JWT、不绕过Origin或权限；已初始化库立即停止。密码登录后丢弃内存引用、不写报告。本次最小真实事务已执行相同建号/登录路径并清理。
4. **保存本地会话。** 正常登录返回的 access JWT 写入本次 `0600` 的 `owner-session.json`，供现有控制脚本使用；同一会话的 refresh Cookie/会话标识仅留在受控内存或私有 Cookie 文件，以便退出。不要把 PAT 或生成用的 API Key 当成控制会话。需要重新登录时丢弃未接入上游的环境重新预置，不向维护者索要已有账号密码。
5. **确认新库的运行资格。** 核对实际 writer、schema、身份配置、历史/未决义务和 Key 资格；新建无历史测试库按既有合法初始化路径配置，不直接搬用老库模式切换步骤。生成调用的有效 `RetryTimes` 必须为 `0`，客户端也不重试。资格不满足时停止，不通过切 writer 或修改历史标记放行。

## 精确动作预算与验收顺序

所有值都是待授权消耗上限，不是必须耗尽的目标。只批准一个 run；重启不接管旧 run，不自动开第二轮。

| limits 字段 | 上限 | 允许用途 |
| --- | ---: | --- |
| `duration_seconds` | 1200 | 从 run 创建起算的主动阶段期限。 |
| `max_auth` | 1 | 既有 channel 的一次旧 Codex OAuth 换码。 |
| `max_refresh` | 2 | 一次明确手动刷新，加最多一次查询链触发的隐式刷新；所有查询共用此额度。 |
| `max_sample` | 8 | 最多四次手动 WHAM usage 查询，每次最多初查及已有逻辑的刷新后重查；不查询或消费 reset-credit。 |
| `max_models` | 3 | 一次模型发现操作，包含最多一次 GitHub client-version 查询、一次模型查询及一次 401 后重查。 |
| `max_generation` | 10 | 单生成并发，最多十次短文本生成尝试，无推理重试。 |
| `max_total` | **24** | 上述五分类共用总上限，`1+2+8+3+10=24`。 |

失败、429 和已申请但随后取消的尝试可能计数，不能返还或挪用分类额度。查询中的一次隐式刷新也必须纳入授权；若它已耗用额度，后续操作可能提前被拒绝。预算不足时保留部分结果，不追加请求“补齐验收”。本机 setup/login、控制接口和本地状态读取不算上游 HTTP；浏览器供应商导航也不计入 MyAPI 进程预算，但仍只允许维护者的一次手动登录流程。

正常顺序：

1. WHAM usage 第一次：确认原生来源、账号连续性证据、套餐/主次窗口、reset 时间和采样时间。有效证据缺失时停止，不伪造可信身份继续 OAuth/refresh。
2. 同一维护会话调用既有 channel 的 OAuth start，由维护者完成旧登录流程并在受控本地工具内交回回调；调用 complete 一次，验证安全落库与同账号连续性。旧固定回调仍为 `http://localhost:1455/auth/callback`，不能换成新 SIWC 参数或把回调粘贴到聊天。授权 flow 有效期为 10 分钟；同阶段不并发 refresh。WHAM usage 第二次验证新凭据。
3. 明确手动 refresh 一次，检查持久化及账号连续性，再做 WHAM usage 第三次。若前序已异常或身份未知，不额外尝试刷新来探测。
4. 模型发现一次；随后先执行两次固定短提示生成，仅在确有未完成验收项时继续，最多十次。保持单并发，不启动工具、compact、WSS/Realtime、诊断生成或其他 provider。第四次 WHAM usage 留作结束前观测；如果自然 429 提前发生，可将此最后一次查询用于允许范围内的现场观测，并提前结束生成。
5. 对照同一账号/各原生窗口，记录 Key 估计分额、采样延迟和外部/未归属消耗；主次窗口分别表达，不相加，不从 Token 或金额伪造原生百分比。没有可观察变化时记录“本次变化不足以判断误差”，不宣称近似算法精确。
6. 只接受自然 429，区分供应商原生限制、本地 `subscription_share_*` 拒绝及一般限流；不主动耗尽订阅，不消费重置额度。没有自然 429 保留待验。下一原生窗口重置观察不属于本轮，不靠刷新或比例变化清零。完整回答缺 usage 仍成功、Token 未知；没有自然缺 usage 样本时不伪造真实验收。

当前普通 Codex Responses adapter 会移除 `max_output_tokens`（`relay/channel/codex/adaptor.go`）；固定短提示不能构成输出 Token 或订阅消耗的硬上限。需要 Token 硬上限作为前提时，不能按本方案开始，应先单独评估适配。20 分钟到期和取消也不能撤销供应商已经收到的操作。

## 停止、证据与清理

1. **先停止，后清理。** 正常完成、到限、到期、账号证据冲突、凭据落库异常或未知发送结果时，停止新的业务操作并调用 stop。正常手动停止须同时满足 `status=stopped`、`owner_current=true`、`operations=0`、`http_in_flight=0`、`generation_in_flight=0`、`drain_error=false`。到期 `expired` 也核对同样的排空计数；`stopping` 不算完成。停止后不再发真实生成来验证拒绝。
2. **异常保留。** 排空失败、落库结果未知或义务未闭合时关闭新增出站并保留受限现场，报告 run ID 和脱敏原因，等待维护者决定。不得先删除数据库/会话/最新凭据、清队列或回填账务来获得“已清理”结论；重建进程也不会恢复旧 run。
3. **只留脱敏证据。** 允许保存准确源码/制品摘要、run ID、分类计数、时间、状态、脱敏账号引用、窗口百分比/reset/采样新鲜度、结果分类和允许的错误 code/请求关联标识、usage 是否提供及近似误差说明。删除或遮蔽身份信息和秘密，不保存完整响应/回调/请求头/正文。建议保留脱敏证据 30 天，由维护者按实际存储管理；本轮不创建定时清理任务。
4. **撤销供应商授权。** 由维护者在供应商实际支持的管理入口撤销本次专用会话/授权，并确认不再需要最新旋转凭据。代理不在 24 次预算之外发起额外 revoke/refresh/生成请求。未确认撤销时标记“待撤销”，本地删除不代表供应商凭据失效；不能先恢复或重用原凭据。
5. **结束本地身份。** 排空和本地义务确认后停用本次测试 Key，通过当前会话调用 `POST /api/user/auth/logout` 并核对撤销 SID。若操作失败，记录未完成；停止实例并封闭出口，不能仅删 session 文件就称已撤销。正式账号和现有 Key 不在清理范围。
6. **删除本次敏感副本。** 在排空、义务闭合和维护者完成撤销后，停止本次进程；按创建清单核对真实路径和所有权，再删除本次 SQLite 及 WAL/SHM、秘密文件、会话/Cookie、浏览器临时配置、原始敏感日志与本次临时密钥。仅删除本次新目录，避免通配清理；不删除维护者原始凭据文件、其他 `/tmp` 项或生产数据。文件删除不保证物理擦除，底层存储销毁按环境能力处理。
7. **回读结果。** 记录进程/监听端口已停止、本次文件清单清理结果、测试 Key/会话及供应商撤销状态。区分已完成、待撤销、待排空/待核查；所有秘密引用只保留脱敏代号。清理证据不得声称撤销了已经发生的上游消耗。
